- Logout and account deletion do not currently guarantee active-workout draft cleanup.

- Some cleanup failures are only development-logged.

Required behavior:

1. Bind workout drafts to an owner
- Extend the saved workout-session payload with the authenticated owner user ID.
- Save the owner ID whenever an active workout or pending save result is persisted.
- When loading a saved workout:
  - Restore it only when its owner ID exactly matches the current authenticated user ID.
  - If it belongs to a different user, do not expose it in Home or WorkoutChecklist.
  - Safely clear the mismatched draft if possible.
  - If clearing fails, keep it hidden and surface a safe internal/user-visible recovery state; never restore it to the wrong user.
- Define legacy ownerless-draft behavior explicitly:
  - Do not associate it with a newly logged-in user automatically.
  - Prefer safely clearing or quarantining it rather than restoring it across an account boundary.
- Preserve pending-result behavior for the same owner.
- Do not use exercise-name lowercasing for database lookups.

2. Sign-out cleanup
- On successful sign-out, clear the active workout/pending-result draft before or as part of finishing the local signed-out transition.
- Do not report sign-out as successful if required local cleanup failed without explaining the limitation.
- Prevent stale draft restoration after the next user signs in.
- Preserve existing Supabase sign-out behavior and error handling as much as possible.

3. Account deletion cleanup
- After a successful delete_user RPC:
  - Clear active workout/pending-result storage.
  - Clear account-scoped local caches relevant to onboarding and units.
  - Invalidate in-memory auth/user state safely.
- If local cleanup fails after server deletion:
  - Do not falsely imply that all local data was cleared.
  - Ensure the app does not restore the deleted account’s draft later.
  - Provide a safe recovery path to a signed-out state.
- Do not change the RPC or server-side account deletion policy.

4. Auth/account transition state
- Reset or guard account-scoped state on sign-out and user-ID changes.
- Ensure an older async request cannot repopulate the next account’s units/onboarding state.
- Keep unrelated app state and normal session restore behavior unchanged.
