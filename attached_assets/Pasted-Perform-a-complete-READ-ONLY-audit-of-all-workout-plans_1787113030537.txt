## Exact audit checks

### A. Plan inventory

For every workout plan, report:

- Plan ID.
- Plan name.
- Day name or day ID.
- Every exercise name.
- Body part.
- Sets.
- Reps.
- Equipment.
- Optional notes.
- Number of times each exercise appears across all plans.

### B. Name normalization

Normalize names only for comparison, without changing source data.

Compare using:

- Exact display name.
- Trimmed whitespace.
- Case-insensitive form.
- Apostrophe variants.
- Hyphen variants.
- Singular/plural differences.
- Common spelling differences.

Report exact names separately from possible aliases. Do not silently merge names.

### C. Catalog reconciliation

For every plan exercise, classify it as:

- Exact catalog match.
- Case/whitespace-only mismatch.
- Possible alias.
- Missing from catalog.
- Duplicate or ambiguous catalog entry.

Report every missing or ambiguous exercise with:

- Plan.
- Day.
- Exact source name.
- Suggested canonical name, if any.
- Reason for the recommendation.

### D. Coaching reconciliation

For every unique plan exercise, check:

- Exact entry in COACHING_NAME_TO_KEY.
- Stable coaching key.
- Matching EXERCISE_COACHING record.
- Required fields.
- Valid breathing string[].
- At least three variations.
- Valid variation difficulty values.

Classify each as:

- Fully covered.
- Mapping missing.
- Record missing.
- Mapping points to missing record.
- Alias requires review.
- Content incomplete.

### E. Form-guidance reconciliation

For every plan exercise, check whether the existing Form button/guidance path supports it.

Report:

- Exact guidance entry.
- Missing guidance.
- Whether the Form button appears.
- Whether the exercise relies on placeholder content.
- Any mismatch between form-guidance name and catalog/plan name.

Do not add images or modify guidance.

### F. Database and persistence path

Trace the code path used when a plan becomes a workout.

Verify:

- How plan exercises become ExerciseSelection objects.
- Whether IDs or names are stored.
- Exact database lookup behavior.
- What happens when an exercise is not found.
- Whether unmatched exercises are skipped.
- Whether session history, sets, PRs, and completion state are affected.
- Whether any plan exercise can display but fail to save.

Do not query or modify production data unless a separate read-only database query is explicitly approved.

If the database lookup is static source only, state that live database coverage cannot be proven from source inspection.

### G. Duplicate and orphan audit

Find:

- Duplicate exercise names within a plan.
- Duplicate names across plans.
- Plan exercises missing from the catalog.
- Catalog exercises never used by any plan.
- Coaching records never referenced by catalog or plans.
- Form-guidance records never referenced by catalog or plans.
- Mapping entries that point to no record.
- Records with no mapping.
- Aliases that resolve inconsistently.

### H. Special characters and naming

Explicitly test names containing:

- Apostrophes.
- Hyphens.
- Parentheses.
- Slashes.
- Ampersands.
- Plurals.
- Numbers.
- Unicode characters.

Pay particular attention to:

- Kettlebell Farmer's Carry.
- Pause Squat.
- Push-ups.
- Muscle-ups.
- Pike Push-ups.
- Diamond Push-ups.
- Wall Walk.

### I. Catalog and coaching totals

Report:

- Total raw catalog entries.
- Total unique catalog names.
- Total plan exercise references.
- Total unique plan exercise names.
- Total coaching mappings.
- Total coaching records.
- Total form-guidance entries.
- Number of shared exercises.
- Number of missing or unsupported references.

Do not assume the totals should match; explain why they differ.
