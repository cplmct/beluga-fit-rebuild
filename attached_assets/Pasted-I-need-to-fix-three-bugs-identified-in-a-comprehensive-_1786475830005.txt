BUG 1 — Timezone UTC bug in streak/week calculations
Files: HomeScreen.tsx AND StatsScreen.tsx

PROBLEM: Both files use a local date conversion function 
(toLocalDateStr or similar) that calls new Date(iso).getDate() 
which uses the device's LOCAL timezone. But started_at is 
stored in UTC. For users in negative UTC offsets (e.g. CDT 
= UTC-5), a workout logged at 23:00 local time is stored as 
04:00 UTC next day — so the streak calculation thinks the 
workout happened on a different day than it actually did.
This causes streaks to be off by 1 day and weekly counts 
to be wrong near week boundaries.

FIX — Create a UTC-safe date string function:

In BOTH HomeScreen.tsx and StatsScreen.tsx, find the 
toLocalDateStr function (or equivalent inline logic) that 
converts ISO timestamps to date strings.

Replace with this UTC-safe version:
function toUTCDateStr(iso: string): string {
  return new Date(iso).toISOString().split('T')[0];
}

Then replace ALL calls to toLocalDateStr(x) with 
toUTCDateStr(x) in both files.

Also update any comparison like:
const today = new Date().toISOString().split('T')[0];
to ensure consistency — use UTC throughout.

IMPORTANT: Only change the date string conversion logic.
Do not change any other logic in computeDailyStreak, 
computeCurrentWeekDays, or any other function.

BUG 2 — ExerciseDetailScreen.tsx — Chart shows warmup weight

PROBLEM: The weightChartPoints derivation uses 
item.sets[0]?.weightKg which is the FIRST set logged.
If a user did a warmup set at 60kg followed by working 
sets at 100kg, the chart shows 60kg — not the actual 
working weight.

FIX — Use the heaviest set per session instead of first set:

Find this line:
const weightChartPoints = sessionHistory
  .filter((item) => 
    item.sets.length > 0 && item.sets[0]?.weightKg != null
  )
  .slice(0, 10)
  .reverse();

Replace with:
const weightChartPoints = sessionHistory
  .filter((item) => 
    item.sets.length > 0 && 
    item.sets.some(s => s.weightKg != null && s.weightKg > 0)
  )
  .slice(0, 10)
  .reverse();

Find this line in the chart data derivation:
data: weightChartPoints.map((item) => item.sets[0]?.weightKg ?? 0),

Replace with:
data: weightChartPoints.map((item) => 
  Math.max(...item.sets
    .filter(s => s.weightKg != null && s.weightKg > 0)
    .map(s => s.weightKg as number)
  )
),
